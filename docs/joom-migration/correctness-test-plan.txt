APPROVED CORRECTNESS VALIDATION PLAN — 2026-11-16

Goal: Spark4.2.1 + JoomComet1.2 keeps ANSI=true and does not publish incorrect results as a successful job. The user accepted the plan; no test or implementation code was being written at that historical snapshot.
English translation finalized 2026-11-18; current execution authorization is in decisions.json and progress is in STATE.json.

Reference and comparison
- Spark4.2.1 without and with Comet; identical input snapshot, ANSI=true and significant settings.
- Check values and types, NULLs, duplicate rows, keys and guaranteed SQL order. Count/checksum alone is insufficient.
- Separately compare outcomes: must succeed/must fail. Comet success instead of a mandatory Spark ANSI error is a correctness violation.
- Do not conceal differences through arbitrary tolerances/broad normalization. For FIRST/LAST/MIN_BY/MAX_BY respect Spark's permitted nondeterminism; fixed fixtures must produce a verifiable result.
- Check initial/executed plans and actual native execution: a comparison that happens to fall back does not test our operator.

Priority regressions
1. Decimal SUM/AVG, mixed Spark-partial/native-final and reverse combinations; preserve overflow flags/guards and new buffer codecs.
2. Separately cover decimal SUM when Spark abandons codegen at runtime: the original NO_CODEGEN guard does not cover that case.
3. Grouped decimal AVG with LIMIT; Spark success must not turn into an additional Comet error.
4. CAST/arithmetic/division by zero; lazy AND/OR/CASE/JVM dispatch and SMJ hoisting of conditional expressions.
5. DATE/DECIMAL RANGE boundary arithmetic in custom windows and existing fallback guards.
6. Active Joom cost model/BoundaryFormats, mixed shuffle, AQE on/off, forced spill; correct results and expected errors.
7. Applicable known silent-result cases independently of ANSI, including invalid UTF8/BINARY-to-STRING.

Release conditions
- Fix confirmed incompatibilities or restrict the corresponding native path BEFORE execution/publication.
- Do not rely on post-write retry/fallback: incorrect data may not raise an exception.
- Where possible, add deterministic automated regression/differential tests in the corresponding feature PRs; explicitly describe significant uncovered cases.
- Finally check the actual shaded release artifact and target GCP paths. Neither a green job nor green CI alone proves equivalence.
- A finite test suite cannot absolutely guarantee the absence of all bugs; the aim is to cover known cases and not release confirmed unsafe paths.

Boundaries
- ANSI=true does not imply approval for allowIncompatible=true.
- Do not touch or include PR#5889 for now; retain the selected base's standard fallback.
- At the original historical snapshot, code, Git, clusters, publication and tests were not being changed/run.

ADDENDUM APPROVED 2026-11-17
