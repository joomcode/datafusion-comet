# Передача одной группы рабочей сессии

Координатор — исходный чат согласования миграции. Рабочая сессия выполняет одну
из G01–G09; G10 создаётся только если нужен отдельный итоговый diff.

## Настройка пользователем

1. Добавить локальный проект приложения с основной папкой
   `/Users/skotlov/d/projects/datafusion-comet`. Сейчас такого проекта в списке нет.
   Одного облачного ChatGPT Project без доступа к локальной папке недостаточно.
2. Исходный чат сохранить координатором; закрепление/имя — только организация UI,
   оно не добавляет памяти или доступа к файлам.
3. Создавать рабочие чаты по одному в Comet-проекте, в Local mode. Не запускать
   два пишущих чата в одном checkout. Fork необязателен: новое задание плюс эти
   документы обеспечивают явную передачу актуального состояния.
4. Для автоматического создания/продолжения отдельных чатов дать координатору
   прямое поручение: создавать рабочие сессии по этому плану, отправлять им задания,
   читать результаты и передавать уточнения. Это пока только инструкция, не согласие.
   Автоматическая обратная отправка сообщений из worker координатору также требует
   прямого пользовательского разрешения; проще сохранять отчёт в файле, который
   координатор прочитает сам. Внутренние subagents не требуют ручных fork-чатов.

## Стартовый prompt (заменить G01 на нужную группу)

```text
Работай в /Users/skotlov/d/projects/datafusion-comet.
Выполни только группу G01 утверждённого переноса Joom Comet1.2/Spark4.2.1.
Сначала прочитай AGENTS.md, docs/joom-migration/README.md, decisions.json,
STATE.json, approved-plan.json и все карточки своей группы из feature-register.json.
Проверь реальный Git HEAD, чистоту дерева и готовность зависимостей группы.
Соблюдай записанные пользовательские разрешения; предложенный сетевой scope
не считать утверждённым без соответствующей записи/прямого согласия пользователя.
Сохраняй атомарные коммиты в указанной feature branch; не меняй source tag13
и зафиксированный upstream base. Сохраняй все утверждённые Joom contracts,
ANSI=true и mandatory-error checks; PR5889 не включать.
До передачи выполни подходящие correctness/integration/packaging проверки;
по возможности локальные performance checks. Не объявляй непроведённые проверки
успешными. Прогресс и следующий шаг сохрани в STATE.json, полный отчёт —
в датированном подкаталоге /Users/skotlov/d/temp. Обнови MANIFEST.json для
изменённых документов. Сообщи branch/head SHA, состав и результаты координатору
через файл отчёта; следующую группу не начинай автоматически.
```

Группа/branch/base SHA/состояние разрешений должны быть указаны координатором
явно в реальном задании. Если новый чат не видит нужные файлы или действующее
прямое разрешение, он сообщает конкретный пробел и не считает историю fork
доказательством отсутствующих разрешений.

## Отчёт при передаче или прерывании

- group/branch; base SHA и текущий HEAD; Git clean/список незакоммиченных файлов;
- worker thread ID, если известен; ответственный за текущее редактирование;
- все карточки: сделано / осталось / использован upstream аналог с доказательствами;
- изменения API/общих файлов, зависимости, конфликты интеграции;
- точные команды тестов, exit codes, paths к логам; результаты и обязательные ошибки;
- native plan coverage, memory/spill/ownership, benchmark условия и ограничения;
- локальные JAR/checksum/build manifest, если уже есть; непроверенные архитектуры;
- блокеры, вопросы, точная следующая команда/подзадача, что НЕ выполнено.

Координатор читает файл отчёта и проверяет Git/test evidence, затем интегрирует
изменения, повторяет нужные совместные проверки и актуализирует STATE.json.
Смена чата/compaction не считается основанием начинать заново готовые стадии.
Не считать завершение worker-сессии автоматическим разрешением stable release.
