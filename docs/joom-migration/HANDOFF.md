## Текущая фаза

**Код не писать до нового прямого указания пользователя.** Первая рабочая сессия
может только читать источники и готовить G01; не создавать feature branch, не
изменять исходники/тесты/build scripts, не начинать builds/downloads автоматически.
Создание чата не является запуском реализации.

## Работа координатора

1. Создавать только текущую рабочую сессию, а не девять заранее.
2. В prompt явно указывать repo и `docs/joom-migration/README.md`, `decisions.json`,
   `STATE.json`, `approved-plan.json`, `PERFORMANCE.md`, cleanup ledger и карточки группы.
   Из корневого AGENTS.md миграционный раздел удалён по просьбе пользователя.
3. Передавать точную группу/branch/base SHA, допустимые действия и последние решения.
   Текущий прямой code hold имеет приоритет над общим разрешением Git.
4. Читать ответ worker, проверять доказательства и сохранять отчёт здесь.
   Отдельные чаты не синхронизируют последующие сообщения автоматически.
5. После разрешения реализации: один пишущий исполнитель на checkout; review и
   исследования можно параллельно. Интеграцию/общие STATE/решения ведёт координатор.
6. Передавать уточнения самостоятельно. Реальный environment blocker или новое
   требуемое решение сообщать пользователю.

## Обязательное содержимое задания

- группа и все её карточки из реестра; цель/границы, branch, точный base SHA;
- последний запрет/разрешение кода, сеть с условием безопасности, запрет публикации;
- источники approved-plan и пользователем предоставленные checkouts;
- ANSI=true correctness/mandatory errors; PR5889 не включать;
- performance по существующим Comet conventions без специальной инфраструктуры;
- точный scope записи; процессная документация только в docs/joom-migration;
- формат отчёта; следующую группу автоматически не начинать.

## Отчёт worker

При подготовке достаточно ответа в чате: координатор прочитает и сохранит его здесь.
Разрешённая связь task-to-task — только по этой работе; сообщений людям не отправлять.
При реализации отчёт сохранять в этом каталоге, raw logs — в датированном temp.

Фиксировать group/branch/base/head/cleanliness, сделанные и оставшиеся карточки,
upstream replacements, изменённые shared APIs, тестовые команды/exit codes/log paths,
native coverage, performance результаты и ограничения, созданные paths/Docker IDs/
volumes/размеры для cleanup, артефакты/checksums, блокеры и точный следующий шаг.
Непроведённые проверки не объявлять успешными.

Смена сессии/compaction не является основанием повторять готовые стадии.
STATE и решения отражают фактический прогресс и прямые пользовательские разрешения;
старые snapshots не должны перезаписывать текущее состояние.
