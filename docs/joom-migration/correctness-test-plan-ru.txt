УТВЕРЖДЁННЫЙ ПЛАН ПРОВЕРКИ КОРРЕКТНОСТИ — 2026-11-16

Цель: Spark4.2.1 + JoomComet1.2 сохраняет ANSI=true и не публикует неверные результаты под видом успешно выполненной job. План принят пользователем; тестовый код и реализация сейчас не пишутся.

Эталон и сравнение
- Spark4.2.1 безComet и сComet; одинаковый snapshot входов, ANSI=true и значимые настройки.
- Проверять значения и типы, NULL, duplicate rows, ключи и гарантированный SQL порядок. Count/checksum сами по себе недостаточны.
- Отдельно сравнивать исходы: должен завершиться/должен упасть. Успех Comet вместо обязательной Spark ANSI-ошибки — нарушение корректности.
- Не скрывать различия произвольными допусками/общей нормализацией. Для FIRST/LAST/MIN_BY/MAX_BY учитывать разрешённую Spark недетерминированность; фиксированные fixtures должны давать проверяемый результат.
- Проверять initial/executed планы и фактический native execution: сравнение через случайный fallback не проверяет наш оператор.

Приоритетные регрессии
1. SUM/AVG decimal, mixed Spark-partial/native-final и обратные сочетания; сохранить overflow flags/guards и новые buffer codecs.
2. Отдельно decimal SUM при runtime отказе Spark отcodegen: исходный NO_CODEGEN guard этот случай не закрывает.
3. GroupeddecimalAVG сLIMIT; успешный Spark не должен превращаться в лишнюю Comet-ошибку.
4. CAST/арифметика/деление на ноль; ленивые AND/OR/CASE/JVM-dispatch и SMJhoisting условных выражений.
5. DATE/DECIMAL RANGE boundary арифметика custom окон и существующие fallback guards.
6. ActiveJoom cost model/BoundaryFormats, mixed shuffle, AQE on/off, forced spill; корректность результатов и ожидаемых ошибок.
7. Применимые известные silent-result cases независимо ANSI, включая invalidUTF8/BINARY→STRING.

Условие выпуска
- Подтверждённые несовместимости исправить или ограничить соответствующий native-путь ДО исполнения/публикации.
- Не полагаться на post-write retry/fallback: неверные данные могут не вызвать исключения.
- По возможности добавить детерминированные автоматические regression/differential tests в соответствующих feature PR; существенные непокрытые случаи явно описывать.
- Финально проверить фактический shaded release artifact и целевые GCP paths. Ни зелёная job, ни зелёный CI сами по себе не доказывают эквивалентность.
- Конечный набор тестов не даёт абсолютной гарантии отсутствия всех ошибок; цель — закрыть известные случаи и не выпускать подтверждённые небезопасные пути.

Границы
